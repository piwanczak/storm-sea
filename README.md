# Storm Sea

A native Android storm at sea. The GPU draws an endless animated ocean with large swells, fine ripples, foam, cloud reflections, sea mist, rain, and occasional lightning. The camera can turn, tilt, travel, change height, and zoom.

Version 1.1 replaces the repeating wave rows with ten uneven wave components, curved wave fronts, and groups that change strength by location. It also adds three layers of visible wind-driven rain with different speeds, lengths, and depths. The rain stays visible when the app lowers its render resolution.

## Install

Build the app with the steps below. Copy `app/build/outputs/apk/debug/app-debug.apk` to your Android device and open it. Allow installation from the file app if Android asks. The app needs Android 8.0 or later and OpenGL ES 3.0. It opens in landscape and works offline. It does not request camera, microphone, location, storage, or network access.

For a device with USB debugging enabled:

```powershell
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

This APK uses a debug signing key for local installation. It is not a Play Store release.

Run `scripts/package.ps1` after a build to export the APK and source archive to `dist/`. The script includes preview images when device captures are available. Build output, local SDK paths, signing keys, and device data are not stored in this repository.

## Controls

| Control | Effect |
| --- | --- |
| Drag with one finger | Turn and tilt the camera |
| Drag with two fingers | Move across the sea in the current camera direction |
| Pinch | Change the field of view from 36 to 92 degrees |
| View height | Move from 3.6 to 28 metres above sea level |
| Storm | Change wave strength and foam |
| Drift | Move slowly forward |
| Rain / Lightning | Enable or disable each effect |
| Pause / Play | Stop or start the storm; camera controls remain active |
| Balanced / High / Low | Change detail and render resolution |
| Reset view | Restore the starting camera |
| Hide controls | Show a clear view, with one button to restore controls |

## Build

Open this folder in Android Studio. Use JDK 17, Android SDK 35, and build tools 36.0.0. The project has a Gradle 9.1 wrapper and uses Android Gradle Plugin 9.0.0. It uses Java and Android framework classes without app dependencies.

On this PC, the build script finds the SDK and JDK supplied with Unity:

```powershell
.\scripts\build.ps1 -Offline
```

On another PC, set `JAVA_HOME` and `ANDROID_HOME`, then run `gradlew.bat assembleDebug` on Windows or `./gradlew assembleDebug` on macOS/Linux. The first build needs an internet connection. Output: `app/build/outputs/apk/debug/app-debug.apk`.

## Device checks

The separate test APK checks shader startup, changing and paused frames, camera bounds, multi-touch transitions, movement, zoom, controls, and pause/resume. It saves device screenshots under `qa/device`.

Screenshot files are generated by the device checks and are not stored in Git. The numerical check code and recorded text results are included under `qa/`.

```powershell
.\scripts\test-device.ps1 -Serial emulator-5586 -Build
```

Use your device serial from `adb devices`. The tests install this app and the test APK, then reset this app's test session.

For a fixed camera comparison after installing both APKs, run `scripts/capture-views.ps1 -Serial emulator-5586`. This captures low and wide views with rain on and off. The wide view uses the maximum 28 metre height and 92 degree field of view. Time, camera position, storm strength, and render detail are fixed for each comparison. Run `node qa/wave-checks-v2.cjs` to repeat the numerical wave checks.

## Render design

`OceanRenderer.java` uses a native `GLSurfaceView` and OpenGL ES 3.0. The fragment shader traces camera rays through a wave height field, computes surface normals, and adds reflected sky, foam, mist, and rain. `waves.glsl` defines the wave groups and their surface slopes. `rain.glsl` defines the falling rain and mist. The renderer inserts both modules into `ocean.frag` before compilation. All geometry and color are generated at run time. There are no video backgrounds or downloaded textures.

The render resolution falls when frame rate stays below 27 FPS. It can recover when the GPU has spare capacity. Actual speed depends on the device. The high setting can use more power. Camera and control state survive Android activity recreation; the wave clock restarts with a new activity.

The visual direction came from [Alexander Green's ocean shader comparison](https://x.com/alexframegreen/status/2096155541244395608). This project uses original shader code. Blender was not needed.
